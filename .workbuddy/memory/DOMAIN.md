## 六、★首屏取数铁律 + 「ensure↔render 自激」死循环（10-10）
- ★★**可降级的取数绝不许进首屏关键路径**。东财腿（`emGet` 单次实测 20.5s；`flowFetchToday` 两侧 41s）从前是 `await Promise.all([云端,东财])` ⇒ **榜单根本不渲染**（用户看到「点哪个板块都没反应」）。现口径：两腿**并行发起、只等云端**（~1s）即渲染；东财腿只给 `FLOW_EM_BUDGET_MS=2500` **硬预算且不重试**，超时判失败（底层不取消）。**冷却期照常渲染云端**，只在口径行注明（旧实现冷却期直接 `return`＝一片空白）。
- ★★**任何 `ensure()` 与 `render()` 互调，必须「成功才重渲 + 失败收敛」**：失败**绝不重渲** + 写**退避窗口**（`FLOW_BRIEF.nextTry`，60s→2m→…上限 30 分钟）+ `logOp` 记流水。实测：旧写法（失败后无条件 `renderDash`）⇒ 无限自激；jsdom 6s 内 `renderDash` **103 次** ⇒ 定时器饿死 ⇒ **整页点击失效**。正确范例：`mlMarketEnsure`（`MLMKT.tried` latch）、`picksEnsure`（失败置 `PICKS.err`）。
- 回归锁：`_tests/_cache/flow-firstpaint-check.js`（23 项）+ `flowbrief-loop-check.js`（15 项）。
- 诊断「事件循环被饿死」：注入 `window.setTimeout` 心跳（**禁用微任务心跳**，递归 `.then` 本身就会饿死定时器）+ `VirtualConsole.on('log')` 落盘；二分用 `_neuter.js` 给函数体插 `return`；卡死进程按 PID 杀（脚本先写 `<log>.pid`）。⚠️**卡死的 node 会烧 CPU 拖垮后续所有测试** → 先查 node 累计 CPU。
