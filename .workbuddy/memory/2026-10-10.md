# 2026-10-10 · 东财「被封」正面解决（换接口域 + 云端预生成）

## 一、用户指令与定性
- 「东财的问题主要是解决被封」→ 「流入前五一直加载不出来，所以要有解决办法。」
- 定性（本机实测钉死）：东财对本机公网 IP 是 **IP 级封禁**，不是频率限流。
  判据：**第一次就拒**（板块级 clist 也直接拒连）；频率风控的表现是「前几次 200、后段 502」。
  ⇒ 降频 / 重试 / 换域名(push2 · push2delay · push2his) / 等冷却 **全部无效**。
  用户浏览器与本机同一出口 ⇒ 线上「点板块看主力净流入前 5 个股」100% 失败。

## 二、★ 突破口 = 换**接口域**，不是换出口
`datacenter-web.eastmoney.com`（另一套风控域，本机 http=200 可用）两个报表一 join 就够：
| 报表 | 内容 | 实测 |
|---|---|---|
| `RPT_BOARD_CONSTITUENT` | **板块 → 成分股**（94,304 行） | pageSize **2000** × 48 页 ≈ 40s；`BOARD_CODE_BK`="BK1033"；**filter 不支持 BK 码**（result=null）⇒ 只能全量拉 |
| `RPT_DMSK_TS_STOCKNEW` | 全市场**个股当日**主力资金（5,200 只） | pageSize **硬上限 500**（传 1000 也只回 500）× 11 页 ≈ 6s；`PRIME_INFLOW` 单位 **元** |
- `PRIME_INFLOW` 单位元（→ /1e4 得万元，与 flow-history 的 mon/days 同单位）；`CHANGE_RATE` %（→ ×100 得 bp）。
- ⚠️ `CHANGE_RATE` / `CLOSE_PRICE` 可能是 **null** → 必须判 null，**不能靠 `isFinite(Number(null))`**（=0 陷阱）。
- F10 `RPT_F10_CORETHEME_BOARDTYPE` 仍可用，但其 `BOARD_CODE` 是**数字码**(879/867)，不是 BK 码。

## 十九、★发现并修复「点击没反应」的第二真凶：flowBriefEnsure ↔ renderDash 自激死循环（2026-10-10 10:1x，已改代码）
- **触发场景（很普通）**：用户**有持仓** + 云端 `flow-history.json` 取不到。
- **机制**：旧 `flowBriefEnsure` 失败时 `ins` 仍为 null、`loading` 又重置 false，却**无条件** `renderDash()`；
  而 `renderDash → holdBoardLine → holdFlowStat` 拿不到数据 → 又调 `flowBriefEnsure()`
  ⇒「渲染 → 补数 → 失败 → 再渲染」**无限自激**。`Promise` 链=微任务，微任务不空 ⇒ 定时器/宏任务饿死 ⇒ **整页点击失效**。
- **实测**（jsdom，6s 内）：`renderDash` **103 次**、`holdBoardLine` **412 次**；`setTimeout(…,300)` 心跳第 2 次永不触发（事件循环饿死）。
- **修法（两条，缺一不可）**：①失败**绝不重渲**（失败没带来新信息，重渲只会再触发自己）；②失败写**退避窗口** `FLOW_BRIEF.nextTry`（60s→2m→4m…上限 30 分钟）+ `logOp` 记自检流水。
- **回归锁**：`_tests/_cache/flowbrief-loop-check.js`（A 段收敛性 15 项 + B 段成功路径仍重渲）。
  ★ **反向锁**：把「失败不重渲」的 `return` **和**退避守卫同时去掉 → 测试立刻卡死（打印完 A 段标题就没输出）⇒ 测试有牙齿。
- ⚠️ **只去掉其中一个护栏不够**（先只删 `return` 时仍 ALL GREEN）——两个护栏功能重叠，反向锁必须同时移除。
- ★★ **通用规律（写进硬约定）**：任何 `X ensure()` 与 `render()` 互调的模式，**成功才重渲 + 失败必须收敛（退避/一次性 latch）**；否则必成死循环。
  本仓库既有正确范例：`mlMarketEnsure`（`MLMKT.tried` latch + 注释里明写「不在这里重画，彻底避开补完即重画的无限循环风险」）、`picksEnsure`（失败置 `PICKS.err`）。`flowBriefEnsure` 是唯一漏网的。

## 二十一、沙盒诊断技巧（本轮新学，复用价值高）
- ★ **定位「事件循环被饿死」**：在页面脚本**之前**注入一个 `window.setTimeout` 心跳（每 300ms 打一行 `console.log`），
  jsdom 用 `VirtualConsole` 的 `log` 事件 + `fs.appendFileSync` 落盘 ⇒ **进程卡住也能从外部读到现场**。
  ⚠️ 心跳**不能用微任务**（`Promise.resolve().then` 递归本身就是无限微任务链，会自己饿死定时器，得出错误结论）。
- ★ **二分定位**：写 `_neuter.js` 给指定函数体开头插 `return`（源码文本级）→ 逐个禁用候选函数，看心跳是否恢复。
  本轮路径：`renderDash` → `holdBoardLine` → `stkbkPick`（→ `flowBriefEnsure`）。
- ★ **精确杀进程**：探测脚本先把自己的 PID 写进 `<log>.pid`，外部 `taskkill //PID $(cat …) //F`。
  ⚠️ 别用 `kill` / `tasklist /FI`（Git Bash 会把 `/FI` 当路径；要写成 `//FI`）。
  ⚠️ **卡死的 node 进程会烧 CPU 拖垮后续所有测试**，表现为「明明改对了还是卡」——先查 node 进程的累计 CPU 时间。
- ★ `VirtualConsole` **没有 `sendTo()`**（本版本 jsdom）→ 用 `vc.on('log' | 'warn' | 'error' | 'jsdomError', …)` 自己落盘。
- ★ 判「A 是否引起 B」的正确姿势：**把改动前/改动后的两份产物放同一探针跑，逐条对比输出**（本轮据此干净地洗掉了 fng-fallback 的嫌疑）。

### ⚠️ 测试环境新坑（必记）
- **jsdom 会让 node 进程无法退出**：`new JSDOM(...)` 之后 `setTimeout` **永不触发**、`process.exit` 也到不了 ⇒ 外部只看到 SIGTERM「卡死」。

- 抗 SIGTERM：`cat 输出文件` 是可靠读数方式；`(cmd > out 2>&1 &); sleep N; cat out` 可在前台超时下拿到结果。
