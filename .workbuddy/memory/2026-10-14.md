## 打板策略模拟器（新模块 `stock-board-sim/`）

**需求**：模拟打板策略——抓全市场最高标，连板区间选股，T+1 开盘买入，跌 5% 止损 + 回撤 10% 止损，资金分 2 份，初始 10 万，输出交割单/收益率/成功率，网页可改金额与板数策略。

**产物**（独立模块，未触碰 console.html / 小程序）：
- `build-dataset.js` — 腾讯 `ifzq.gtimg.cn` **不复权**日线（220 根 × 4415 只，104s 零失败）→ 自建交易日历 → 重建每日连板数 → 只保留曾连板≥2 的 1113 只 → `output/dataset.js`（6MB，挂 `window.__DATASET__`，file:// 可直载）
- `lib/strategy.js` — UMD 引擎，前后端同一份；**全程整数分运算**（避免浮点导致涨停误判），默认 `3 < 连板 < 5` → 只买 4 板
- `index.html` — 参数面板 + 资金曲线 + 交割单 + 卖出原因分布，改参秒级重算
- `run-backtest.js`（可 `--csv`）、`sweep.js`（参数扫描）、`verify-data.js`（东财交叉验证）、`audit.js`（引擎自审）、`selfcheck.js`（前端静态自检）、`server.js`（8777）

**★数据源结论（更新口径）**：
- `push2ex.eastmoney.com/getTopicZTPool` **可用**（73ms），但带 `date=` 时仍返回最近交易日池，不能当历史源
- `push2his.eastmoney.com` K线 **可用**（99ms，但偶发 socket hang up，不可靠）
- `push2test` 的 ZTPool 路径 → **404**（与旧记忆相反，旧记忆说 push2test 是唯一可用的）
- 腾讯 `ifzq.gtimg.cn`（无前缀）与 `web.ifzq.gtimg.cn` **均可用**；`param=CODE,day,,,N,`（无 fq 后缀）= 不复权，`qfq` = 前复权

**★踩坑（必须记住）**：
1. **持仓天数用了错的索引坐标系** —— 买入时记的是「票内 bar 索引」，卖出却拿「全局日期索引」相减，导致出现「当日买入当日卖出、持有 0 天」的假交易。统一改为 `entryGIdx = t`（全局索引）收口。
2. **A股 T+1 硬约束** —— 买入当日必须跳过全部卖出判定（但当天最高价仍要计入 highWater）。
3. **跌停锁死卖不出** —— 开盘即跌停、以及收盘跌停，挂单都无法成交，必须顺延次日；否则「到期强平」会用一个不可能成交的收盘价成交，虚增亏损。
4. **资金守恒等式** —— `期末 = 初始 + 已平仓净盈亏 + (未平仓市值 − 未平仓成本)`，漏掉成本项会凭空多出一笔持仓成本。
5. 「回撤止损按当日冲高回落」**不是乐观假设**：同一日内 h 与 l 价差达 10% 即说明盘中真发生了该幅度回落，与先后顺序无关，等价于日内移动止损单。

**验证强度**：
- 连板数据 vs 东财涨停池独立核对：**命中 100%、连板数完全一致 92/92**
- `audit.js` 五项全绿：买入价＝买入日开盘价、卖出价落在当日 [low,high]、T+1 纪律、止损容差（4 笔因一字跌停锁死豁免）、资金守恒差 **0.00 元**

**回测结论（真实、偏负面）**：
- 默认档（4板 / 次日开盘买 / 止损5% / 回撤10% / 断板即出 / 2 份）：60 日 **−32.01%**（成功 36.1%），175 日 **−69.17%**（成功 34.4%）
- 亏损主因：**14 笔「开盘跳空跌破止损」累计 −7.30 万** —— 4 板票次日低开是常态，止损线直接被跳空击穿；另有连续一字跌停锁死导致单笔 −25%
- 5 板/6 板档位反而为正（+27% / +7.6%），但样本仅 45 / 20 笔，**不可外推**

## 补充（19:25）打包单文件版 —— 解决"换个环境就打不开"

**问题**：`index.html` 依赖外部 `output/dataset.js`（5.9MB）与 `lib/strategy.js`，一旦脱离项目目录就废掉（WorkBuddy 预览托管是**会话级**的，本地 `node server.js` 后台进程也会随会话回收 → 两端口均 ECONNREFUSED）。

**方案**：`build-standalone.js` 把「页面 + 引擎 + 数据」内联打包成单文件 **`打板策略模拟器.html`**（3.4MB，零外部依赖）；数据用 `zlib.gzipSync` 压缩后 base64 内联，前端用浏览器原生 **`DecompressionStream('gzip')`** 解压（实测 42ms）。已接入 `build-dataset.js` 末尾，重建数据后自动重打包。

**验证**：零外部依赖 ✅ / 内联脚本 3 段语法通过 ✅ / 数据可解压还原 ✅ / **端到端回测结果与直读 dataset.json 完全一致（36 笔、−32.01%）** ✅

**经验**：给用户的单页交付物，只要依赖外部数据文件，就必须提供**自包含打包**——否则预览面板/临时服务器一收就变成一堆报错。

## 补充（20:47）咨询：打板策略做成自动化交易的路径

用户问「如果做成打板自动化交易怎么做」。已核实监管/通道/下单规则，给出**三层架构**（信号层→执行层→风控层），**待用户确认落地范围**。

**下单通道（核实）**：QMT（迅投，本地跑，Python/VBA，自由度高）/ PTrade（恒生，云端托管，内置条件单模板）；门槛 10 万（国金/银河/方正/华宝）～50 万（华泰/中信）；风险测评需 **C4/C5**；★**必须通过客户经理开通，自助开户的账户没有量化白名单入口**。

**★核心区分（最重要）**：本策略是「**次日开盘买入**」≠「涨停瞬间排队打板」。前者只需**集合竞价预埋限价单**，自动化难度低；后者散户**基本排不进**（2026-03 券商交易单元整改：暂停新申请且不得单账户独占；2026-07 交易所机房行情接入由局域网转广域网 → 限速）。

**★下单铁律**：
- 打涨停必须用**限价单指定涨停价**（QMT `price_type=xtconstant.FIX_PRICE`；passorder `prType=11`）。用「对手方最优价」市价单会在涨停（盘口无卖盘）时被交易所**废单/自动撤单**。
- **撤单重挂＝排到整个队列最尾**，此前排队全废 ⇒ 只在明确放弃时撤。
- 隔夜预埋单：券商清算后（约 20:00–22:00）才接收，**次日 9:15 统一报送交易所**；同券商内越早越靠前，跨券商不可比。9:20–9:25 不可撤单。
- ⚠️ 市面「打板 VIP 快速通道 / 一键抢板神器」**全部是骗局**，且违反交易所规则（第三方外挂不合规）。
