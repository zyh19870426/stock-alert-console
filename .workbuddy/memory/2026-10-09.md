## 七、东财方向确认：用户要的是「解决被封」，不是绕过
用户原话：「**东财的问题主要是解决被封**」⇒ 方向从「前端降级 / 换源」修正为**正面解决封禁**。

**★ 复测确认（本机，10-09 23:36）**：本机公网 IP 已被东财 **IP 级封禁** ——
`push2delay` 板块级 clist、`push2` 个股级 clist **都是 `fetch failed`**（连板块级都拒），
只有 `push2ex`（涨停池，独立风控域）仍 `http=200`。
⇒ **结论：降频 / 重试 / 换域名 / 加冷却全部救不了**（那是对付「频率风控」的手段）；
用户浏览器与本机同一公网出口 ⇒ **浏览器直连 push2 同样会被拒**。唯一出路是**换出口 IP**。

**两条正面解法**：
- **B 云端预生成**：把「板块前5个股」从「用户点开时才请求」改成「Actions 每天定时抓一次 → 前端读存档」，
  用户侧东财请求降为 **0**。**前提**：Actions IP 能抓个股级 clist —— 2026-09-30 旧结论是 502（个股级挂、
  板块级可用），**风控策略会变，必须复测**。
- **C 代理中转**：前端请求走自建 Worker（Cloudflare Workers / 云函数），出口 IP 干净且可换，
  再加**全局共享缓存**（同一板块 5 分钟内只打一次东财）—— 这是最彻底的解法，代价是要引入一个常驻服务。
- **D 换源（兜底）**：新浪 `MoneyFlow.ssl_bkzj_ssggzj` 已实测可用（等价接口），但东财↔新浪板块
  名称匹配率仅 11.8%，需先解决映射。
